# Лабораторна робота № 6 — алгоритми сортування

**Варіант:** 4  
**Тип масиву:** float[]  
**Порядок:** за спаданням  
**Алгоритми:** Bubble sort і Selection sort

## Програма

Клас Lab06 містить два методи сортування. Кожен метод змінює переданий масив на місці й викидає NullPointerException, якщо замість масиву передано null. Для порівняння float використовується Float.compare.

Обидва алгоритми сортують числа за спаданням. Наприклад, масив [3.5, -1.0, 0.0, 8.2] після сортування матиме вигляд [8.2, 3.5, 0.0, -1.0].

Float.compare задає також порядок для особливих значень: NaN у порядку спадання опиняється перед звичайними числами; додатний нуль вважається більшим за від’ємний нуль.

## Контрольні питання

### 1. Переваги та недоліки Bubble sort, Selection sort та Insertion sort

**Bubble sort (сортування бульбашкою)**

Переваги: простий; сортування на місці; стабільний; оптимізована реалізація завершується за O(n), якщо масив уже відсортований.

Недоліки: у середньому та найгіршому випадках виконує O(n²) порівнянь і переміщень; для великих масивів повільний.

**Selection sort (сортування вибором)**

Переваги: простий; сортує на місці; виконує лише O(n) обмінів, що корисно, коли запис у пам’ять дорогий.

Недоліки: завжди виконує O(n²) порівнянь, навіть на вже відсортованому масиві; стандартна реалізація нестабільна.

**Insertion sort (сортування вставкою)**

Переваги: простий; стабільний; сортує на місці; ефективний на малих або майже відсортованих масивах; найкращий випадок має час O(n).

Недоліки: у середньому та найгіршому випадках має час O(n²); для великих і зворотно відсортованих масивів повільний.

### 2. Порівняння алгоритмів за часом, пам’яттю та стабільністю

- **Bubble sort:** найкращий час O(n) з перевіркою обмінів, середній і найгірший — O(n²); додаткова пам’ять O(1); стабільний.
- **Selection sort:** найкращий, середній і найгірший час — O(n²); додаткова пам’ять O(1); зазвичай нестабільний.
- **Insertion sort:** найкращий час O(n), середній і найгірший — O(n²); додаткова пам’ять O(1); стабільний.

Стабільний алгоритм зберігає відносний порядок рівних елементів. У цій програмі Bubble sort стабільний, а Selection sort — ні.

Інші критерії порівняння: кількість порівнянь, обмінів і записів; адаптивність до початкового порядку даних; простота реалізації; розмір масиву.

### 3. Найкращі та найгірші випадки для алгоритмів

Для оптимізованого Bubble sort та Insertion sort найкращий випадок — уже відсортований за спаданням масив: вони можуть пройти його за O(n). Для них найгіршим є масив, відсортований за зростанням: потрібно виконати O(n²) роботи.

Selection sort виконує O(n²) порівнянь і для відсортованого, і для зворотно відсортованого масиву. Кількість обмінів залишається O(n).

Отже, для майже відсортованого масиву найкраще підходять Insertion sort або оптимізований Bubble sort. Для масиву у зворотному порядку жоден із цих трьох алгоритмів не стає лінійним; Selection sort може бути кращим за кількістю записів, але за кількістю порівнянь усе одно має O(n²).

### 4. Що означають O(1), O(n), O(n²)?

Це позначення асимптотичної складності, яке описує, як зростають витрати алгоритму зі збільшенням кількості елементів n.

- **O(1)** — стала складність: кількість операцій приблизно не залежить від n.
- **O(n)** — лінійна складність: подвоєння n приблизно подвоює кількість операцій.
- **O(n²)** — квадратична складність: подвоєння n може збільшити кількість операцій приблизно в чотири рази.
